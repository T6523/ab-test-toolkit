2. What does my result say?

Type the counts from a finished test. Delta is the smallest lift worth shipping and should be chosen before looking at results. The defaults are the example in the repo: significant, but not clearly worth shipping.

3. What goes wrong when you peek?

A/A tests (no real effect). Checking the ordinary z test at every look and stopping at the first "significant" result inflates false positives far above 5%. Calibrated sequential boundaries keep them near 5%.

Watch one test where nothing is really different

Both groups are identical, so any "winner" is a false alarm. The blue line is how strong the evidence looks after each check. Higher means it looks more like a real difference. A rule declares a win the first time blue goes above its bar. Peeking uses a flat bar at 1.96 (orange). The sequential rule uses the green curve: a very high bar early, when there is little data and flukes are common, falling to nearly the same bar at the end. That strict early bar is why the sequential line in the chart above stays near 5%.

4. What does low power do to your result?

With too few users, the runs that reach significance are the ones where noise pushed the estimate far above the truth, so a "win" overstates the effect.

Source, tests and method notes are in the GitHub repository. Python runs through Pyodide, and charts use Chart.js. Simulations use fixed seeds, so the same inputs give the same numbers.
